# sanakan.pl

Website of [Sanakan](https://sanakan.pl), a Discord bot written in C#. Every page shares a skinnable HUD, modelled on the Safeguard scanner from BLAME!, with dark purple as the default and light palettes supported too. The site itself is in Polish.

Echidna and explicitly light custom designs share heading shadows, logo glow, page glow strength, card fills and the home page's Japanese subtitle accent through palette roles in `css/skins.css`. Custom effects use the saved text and accent colours. The light editor defaults follow Echidna's displayed gradient, including `--page-bg-mid`; existing saved colours remain intact. Both croppers consume the same background and heading roles as the main site.

The default HUD and ready-made dark skins preserve the original grey text hierarchy: `--text-body` for descriptions, `--text-secondary` for parameters, `--text-muted` for captions and `--text-dim` for less prominent notes. Light palettes derive these roles from their own text colours; dark custom designs keep the dark hierarchy while allowing the saved text colour to tint it. `--text-strong` is reserved for emphasis and interaction states, rather than ordinary descriptions. The command text colours and original dark palettes have browser regression coverage.

Status charts and API methods share Discord status colours through `--success-tone`, `--warning-tone`, `--danger-tone` and `--info-tone` colours. Text and badges use contrasting ink and readable variants of these colours. API group headings and their subtle hover use the skin's accent. Lore keeps separate roles: `--network` for the recognised gene and terminals, `--discovery` for the Builders' door, `--failure` for the amber 500 page, and `--maze-*` / `--snake-*` for the games. The snake resolves CSS colours before drawing its canvas and repaints when the skin changes, including while paused. The account menu and skin picker share `--panel-surface`, `--panel-border`, dividers and interaction fills. Ctrl+K and the Netsphere console share `--overlay-panel`, keeping dark skins deep and lightly tinted while light skins use a light surface. `--overlay-backdrop` and `--search-selected` style the search, and `--console-backdrop` / `--console-alarm-backdrop` handle the console's normal and alarm states.

`css/skins.css` is the common source of UI colours for the whole site, Swagger and both croppers. Its default palette and per-skin inputs derive `--surface`, `--surface-raised`, `--surface-input`, `--surface-hover`, `--surface-selected`, `--heading`, `--text-muted`, `--text-subtle`, `--link`, borders, focus and status colours. Component styles use these roles; keep palette literals there rather than adding local grey or purple variations. Set `--scheme: light` for a light skin. Custom designs default to the dark purple HUD. Their explicit base selector chooses dark or light styles and native controls; background brightness never selects a base automatically. Legacy designs without a base remain dark. A skin's `--skin-logo` also supplies the homepage's glitch slices. Both croppers share `apps/shared/cropper.css` and load the same palette; frame artwork and media pixels keep their own colours. `php tools/asset-versions.php` embeds the default palette into `offline.html`, which needs no external stylesheet or script, before updating asset versions. Browser regressions in `tests/theme-browser.mjs` check contrast, modal surfaces, forms, API and the production croppers in light and dark palettes, including mobile layouts.

Skin metadata lives in `inc/skin-catalog.php`, with unlock checks and account preferences in `inc/auth/skins.php`. `php tools/asset-versions.php` generates `js/skin-catalog.js` from that metadata and versions linked assets; the existing pre-commit hook runs it too. Add a skin there, its logo in `skins/` and its colours in `css/skins.css`. `js/appearance.js` applies cookies and account colours on every page, keeping a temporary visit override above the saved preference; `js/appearance-picker.js` handles profile previews and the translation switch. On the home page, `js/skins.js` renders the logo, `js/home-language.js` translates and restores text, and `js/home-ja.js` supplies Japanese words and decorations (`css/home-ja.css`). The April discovery is separate in `js/home-april.js` and `css/home-april.css`.
Collecting every normal and seasonal find unlocks **Własny skin** in the profile; the owner gets it immediately, like every other skin. A permissions preview suspends that bonus, allowing the custom skin only with a complete earned register, and preserves its saved design and choice. Its editor offers a dark (default purple) or light (Echidna) base and accepts seven `#RRGGBB` colours (with colour pickers and live previews) an optional image from the account's own gallery folder, including subfolders, and **Animacja tła**: any skin's background animation, or none (`CUSTOM_SKIN_BACKGROUNDS` in `inc/auth/custom-skins.php`, kept in step with `--season-background` in `css/skins.css` by `tests/test_skins.php`), previewed at once and worn wherever the custom skin is. Base palettes are read from `css/skins.css`, so the editor and server do not duplicate colours. Switching bases keeps separate colour drafts for that preview; saving stores the active base. Designs live in `custom-skins.json` and survive selecting another skin. The server validates unlock permissions, colours and image ownership; gallery files retain their normal authentication and token URLs. Deleted or inaccessible images fall back to Sanakan's logo. Losing unlock permission disables the custom skin without deleting its design. The HUD variant, role colour and their explanation appear only for the default skin; switching back restores their values. The animation switch belongs to the skin settings and controls seasonal backgrounds too; saving it preserves the HUD preferences.
Seasonal backgrounds live in `js/seasonal-background.js` and `css/seasonal-background.css`. Sakura returns every 2–15 April, the day after April Fools: catching one falling petal earns `sakura` and unlocks March 7th and Raiden Shogun; March 7th wears the petals, Raiden Shogun violet lightning of her own. Perseids return every 1–15 August: stars twinkle and comets fall; catching a comet earns `perseids` and unlocks Suisei and Hoshino Ai; Suisei wears the comets, Hoshino Ai an idol's stage of her own, sweeping stage lights and twinkling stars. These skins bring their colours, logos and matching backgrounds all year, declared by `--season-background` in `css/skins.css`; profile previews change the background immediately. Seasonal backgrounds remain alongside a different skin's background during their event. Outside the season, a skin's background is decorative and awards no finds. Backgrounds appear on pages using Safeguard, keep controls clickable, pause in a hidden tab and leave stationary targets available with reduced motion or keyboard focus during the season. The server witnesses the catch before the browser records it; anonymous proofs synchronize after login. Preview them with `localStorage.setItem('safeguard-date', '04-10')` or `'08-10'` and reload (remove the key to restore the date).

The **Night of Fireflies** returns every **15–30 June**. Catching a slowly wandering, pulsing celadon or peach firefly earns `fireflies` ("Światło w Megastrukturze") and unlocks **Firefly** and **Yoimiya**. Firefly uses pale celadon and pearl on deep green; Yoimiya uses tangerine and peach on warm brown. Both skins keep the same fireflies all year, decorative outside June 15–30, sharing one scene during the event. The lights adapt to light skins, stop with reduced motion and in hidden tabs, and keep one keyboard target during the event when animations are disabled. Preview with `localStorage.setItem('safeguard-date', '2026-06-21')` and reload; server proofs outside the season are available only in the local preview. Character logos live in `skins/firefly.webp` and `skins/yoimiya.webp`; replace those files to update the artwork.

**Teto** and **Miku** wear an equalizer along the bottom edge (`tetosong`, `mikusong` in `css/skins.css`), with a music button in the bottom left corner that plays the skin's song in a loop at 40% volume, or at the volume of the slider beside it, which the browser keeps in `localStorage`. The bars follow the song's spectrum through Web Audio, low notes in the middle; without the song they sway idly, and they stay still with reduced motion. Nothing is downloaded before the button is pressed. Through the Media Session API the lock screen, headphones and media keys show the song with the skin's logo and pause or play it like the button. The tab remembers in `sessionStorage` whether the song played and where, so it carries on across pages, or at the first touch when the browser holds sound back. The songs are `audio/teto.webm` and `audio/miku.webm` (Opus, 160 kbps), with `audio/teto.mp3` and `audio/miku.mp3` for a browser without Opus such as an older Safari, kept out of git (`.gitignore`): copy them there by hand (an Opus file from the MP3: `ffmpeg -i audio/teto.mp3 -map 0:a -map_metadata -1 -c:a libopus -b:a 160k -vbr on -compression_level 10 -application audio audio/teto.webm`), and `deploy.sh` sends a song when the server has none or a different one, then purges it from Cloudflare. Without the file the button shows that the song could not be loaded.

Fauna and Padoru bring the existing glyph snow all year. `js/safeguard.js` owns a single snowfall shared by the skin and the winter period (20 December–20 March), including profile previews, so these never double up. **Animacje skina** in the skin form controls all skin backgrounds and winter snow, previews immediately and saves with **Zapisz skin**. It retains the former snow preference (`inc/data/snow.json` and the `snow` cookie); `js/appearance.js` applies it before paint and reconciles it with the account response. Disabling effects hides decorative backgrounds; Sakura and Perseids still offer one stationary keyboard target during their event. Reduced motion hides snow and makes the other decorations stationary; hidden tabs pause their animations. Tomie adds falling ink drops and spreading pools; Lain adds faint scan lines, signal paths and narrow bands of interference behind the content. The Friday the 13th title glitch and its discovery keep their existing calendar and interaction.

Echidna brings green butterflies with independently timed wingbeats and wandering paths, using her light palette. Marisa brings floating gold dust and occasional little stars with short trails aligned to their flights. These Halloween skin decorations run all year, obey **Animacje skina**, pause in hidden tabs and become stationary with reduced motion. Phones use fewer particles. The October 31 Silicon Creatures and their discovery keep their existing interaction; these skin backgrounds add no finds or clickable targets.

Ayame and Albedo share golden fireworks in the background all year, using the existing New Year rocket and burst renderer from `js/safeguard.js`. Rockets follow a curved climb and burst into glowing trails that slow down, bend under gravity and leave smaller fading embers. Switching between the two skins keeps the same layer and cadence. Disabling animations or leaving the skin stops its timer and removes its sparks; hidden tabs pause it, and reduced motion suppresses the fireworks. Phones use smaller bursts. The single winter snowfall and the event's interactive rocket keep their existing behaviour.

Reisen brings slowly drifting lavender motes; Pekora brings small rabbits hopping in both directions along the bottom edge. Both Easter skin backgrounds run all year, share the animation switch and preview lifecycle, pause in hidden tabs and become stationary with reduced motion. Phones use fewer particles and rabbits. The existing Easter egg hunt remains clickable, including when skin animations are off; these decorations add no finds.

Cibo brings a generated mesh of barely visible points and links carrying small lavender signals. The mesh adapts to the viewport, caps its density on large screens and uses fewer nodes and signals on phones. Killy brings steel dust and glowing embers. Both birthday skin backgrounds use the shared decoration lifecycle and animation switch and pause in hidden tabs. Reduced motion leaves a stationary mesh without signals for Cibo and stationary particles for Killy. The birthday cake remains a separate interactive event.

The profile's **Zmień skin** button opens a modal with thumbnails, names and three colour swatches read from the skin stylesheet (`js/skin-picker.js`). Filters show unlocked or all skins, with the default and named custom reward first. Clicking a tile previews its colours and shows the description below the grid; Escape, Cancel and the backdrop restore the previous choice. Confirming updates the profile form; **Zapisz skin** persists it. The native select remains available without JavaScript. Locked ready-made entries show `???` and their unlocking group without revealing names, artwork or identifiers. **Własny skin** always shows its name and collection progress, even while locked. The owner bonus is suspended during a permissions preview, which keeps earned skins and the saved preference intact. Account replies remove a skin immediately when its discovery or session is gone, restoring the original logo and words; an April look deliberately activated for the visit remains independent of the account.

The top right corner of the home page logs in with Discord (`account.php`); the API button unlocks for the accounts that may read it. Every page of the site shows the logged-in account there the same way: its avatar ringed in the accent of the HUD (the site's purple, or the colour picked in the profile), the name and its Safeguard level in the colour of its role on the bot's Discord server, e.g. `LV.9` for a dev or `LV.3` for a moderator. A click opens a menu in HUD corners with the profile, the gallery and the panel (these two only for the accounts that may open them), logging out (set apart by a line, back to the same page) and a line with the full role, e.g. `LV.9 DEV`, and the account ID. Dev, admin, semi-admin and tester open the API documentation, admin and dev also the private commands; any role, user and up, gives a folder of its own in the gallery and the choice of the HUD colour. Seeing and managing the whole gallery has its own lists and never follows these roles. A short click on the status dot opens `/state/`; held for 3 seconds it fires the beam of the Gravitational Beam Emitter from BLAME!. Typing `netsphere` on any page (or tapping the `SAFEGUARD · LV.9` line five times) asks the Netsphere for access: the Safeguard scans for the Net Terminal Gene, does not find it and marks the visitor an illegal resident. Then its emergency terminal stays open: `pomoc` lists the commands, `status` and `ping` ask the site, `whoami` shows the account's level, `idź` goes to a page, `man` to a command, `rejestr` lists the finds below, and words from BLAME! (`killy`, `cibo`, `sanakan`, `budowniczy`, `silikon`, `dhomochevsky`, `administracja`, `emiter`) answer with its lore (`js/netsphere.js`).

Ctrl+K (⌘K on a Mac), or "Szukaj" the script puts in the footer of every page, opens the search of the whole site: its pages, the bot's commands and its versions (`palette.php`), picked with the arrow keys and Enter (`js/palette.js`, its styles in `css/palette.css`, apart from `css/style.css` so Skalpelator and USkalpelator take it too; their other easter eggs stay out, as the keys and the snow would get in the way of the cropping). A service worker (`sw.js`, registered on every page) shows `offline.html` when a page cannot be reached for want of a network, and nothing else: with a network every request goes on as before.

Every find needs a proof from the server, its time, a random nonce and the find signed with `SAFEGUARD_SECRET`, so `SanakanSafeguard.found()` in the console or `localStorage` edited by hand gives nothing: the answers of `megastructure.php` that make the finds of the way to the gene carry it, and the others it witnesses as well as it can (`?witness=`, `megaWitness()`): a seasonal find only on its day (Polish time, give or take 14 hours for other time zones), the idle page, the shot and the broken logo only as long after a ticket of when they began (`?ticket=`), Killy only with his ticket, each ticket good for its find once, so passed on it gives nobody another (`inc/data/tickets.json`), the header's password only right; the scan, the console, the Konami code, the lore, the network lost, the Morse code and the 404 are as easy to make as to fake, and their proof only puts the server's time on them. One more the server checks whole before it gives it (`snakeAnswer()`), keeping an account's best result (`inc/data/snake.json`), which the ranking shows. The way to the gene goes in its order: a step counts for an account only after those before it (`megaChainFinds()`), and the maze answers only a walk that carries the proof of floor zero. A proof counts for the first account that sends it (`inc/data/proofs.json`), and every proof given out is a new one, so two visitors in the same second never share one. A find is kept in the browser (`localStorage`) with its proof and goes to the account at once, or after the next login, through `account.php?finds`; the profile lists them in `inc/data/finds.json`, and `/hunters/` ranks the accounts by them and lists, for each secret, who made it and when, the admins and the flagged accounts among them without a place. An account whose new finds could not have been made, the Builders' hour outside it, more than 3 finds within 5 seconds, 5 within 2 minutes or a step of the way to the gene sooner after the one before than it can be made (`MEGA_CHAIN`), is flagged by the Safeguard: listed last in the ranking, without a place, out of who found each secret first, and told so in its profile; the panel's profile of an account (`/admin/?konto=ID`) shows its register, takes back one find or all of them (gone from its browser on its next visit too) and sets or takes off the flag.

The register's account steps (`builders`, `floor0`, `maze`, `paper`, `gene`, `admin`) have their account ID included in the proof's signature. Another account cannot claim even a fresh proof or use its floor-zero proof for the maze. Finds already recorded in `finds.json` remain unchanged; old, unclaimed proofs of these steps must be obtained again because their original owner was not recorded. Anonymous discoveries outside that chain can still be claimed after login. The browser keeps the first pending proof and queues distinct replacements in `localStorage`, so recollecting a step preserves its original order. A rejection applies only to the proof that was sent; queued replacements are tried in register order, and following steps remain pending while an earlier proof is retried. Confirmed or withdrawn finds clear their replacement queue.

Games and ticket redemption use POST with a session CSRF token from `megastructure.php?csrf`, also for anonymous players. A ticket's issued proof is saved atomically in `tickets.json`; retries return that exact proof, with its original time, and it can still be claimed by only one account. The browser retries a failed write once. Ticket issuance is limited to 60 per address per minute (an IPv6 /64 counts as one address), with HTTP 429 and `Retry-After` when exceeded. The rate store has at most 2048 active addresses and the ticket store at most 10000 entries (`MEGA_TICKET_*` constants); expired entries are removed by their own lifetime, and a full ticket store refuses new entries with HTTP 503 while existing retries remain available. Valid games can still be automated: replay validation and minimum elapsed times do not prove a human played them.

## Skalpelator and USkalpelator

The two croppers are Svelte apps with their sources in `apps/skalpel/` and `apps/uskalpel/`. Vite builds them with the base `/skalpel/` and `/uskalpel/` straight into the site's `skalpel/` and `uskalpel/`, which are committed, so `deploy.sh` sends them like any other file and deletes what a new build left out. After a change to an app (Node.js 22.12 or newer, which Vite 8 needs):

```bash
tools/build-apps.sh            # both, or: tools/build-apps.sh skalpel
```

and its sources go into the commit together with the build. CI builds them again (`npm ci`, so exactly the versions of `package-lock.json`) and fails when the committed build is not the one of the sources. For working on one, `npm run dev` in its folder serves it with live reload; what belongs to the site (its fonts, icons, `account.php`, the gallery) it takes from the site running locally (see Running locally), or from the address in `SANAKAN_SITE`. The code both use is in `apps/shared/`; what of it runs without a page (which `blob:` addresses an app lets go of, `ownedUrls.js`, how many decoded pictures the renderer keeps, at most 4 and 256 MB, and the draft of the work, `draft.js`: settings written a moment after a change, a picture only when another takes its place, and all of it before a login link leaves the page) is tested by `node --test apps/*/test/*.test.mjs` with USkalpelator's frames (`apps/uskalpel/src/lib/frames.js`: which pictures of the bot make up each frame) and layers (`apps/uskalpel/src/lib/layers.js`: Scalp kept over the opening of its frame's mask, so nothing behind it shows, and in Obie both layers moved, zoomed and stopped at the edge alike) and Skalpelator's opening (`apps/skalpel/src/lib/opening.js`: the picture stays 448x650 as the bot expects it, but only has to cover, with 2 px to spare, the part all the bot's frames leave open, so it can be moved and zoomed out up to what the frame hides), both on `apps/shared/lib/cover.js`, also in CI. The apps let go of every `blob:` address they made once it is no longer shown and when they go, drop a crop, a file read or a removed background that ends after a newer one was asked for, and keep what the user did when the styles of the frames (`/pw/variants.json`) come late; a failure to get them says so and can be tried again. Their fonts are the site's own (`css/fonts.css`, linked in their `index.html`, its `?v=` kept up to date by `tools/asset-versions.php` like any page's).

Their header is the site's: `apps/shared/lib/Header.svelte` puts in the account menu of every page through the site's own `js/account.js` and `css/account.css` (the account's styles, split from `css/style.css` so the apps can take them without the site's whole stylesheet), linked in their `index.html` with `js/appearance.js`, which gives them the HUD colour the account picked; the search of every page comes the same way, `js/palette.js` and `css/palette.css`, after the app, whose footer gets its button. `account.php?back=<page>` makes logging out come back to the page asking, and also says whether the account has a folder of its own in the gallery (`own`) and its CSRF token; `account.php?login&back=<page>` logs in and comes back there. "Do galerii" (`apps/shared/lib/GallerySave.svelte`) sends the card to `i/` with the action `cropper`, which makes the folder `Skalpelator` (`CROPPER_DIR`) in the account's own folder the first time and from there is an upload like any other, with the same limits. The card goes as a lossy WebP made in the browser (`apps/shared/lib/webp.js`: libwebp in WebAssembly, `@jsquash/webp`, loaded at the first save; quality 98, method 6, sharp YUV, lossless alpha) from the very pixels the PNG of "Pobierz obrazek" has, which the gallery keeps as it is. The answer of every upload carries the file's link and its folder (`uploadedLinks()`). "Z mojej galerii" (`apps/shared/lib/GalleryPick.svelte`) lists the pictures of the account's own folder, subfolders included and newest first, from `i/?pick` (`pickList()`, JSON with each one's link and thumbnail; 401 without a login, 403 without a folder of its own), and crops the one chosen; it is on the site, so the crop reads it without asking another server.

They run in the browser alone, saving into the gallery apart: the pictures of the cards come from the site's own copy at `/pw/` (`inc/pw.php`), and USkalpelator's background removal (`@imgly/background-removal`) takes its model and onnxruntime's WebAssembly from IMG.LY's CDN, so the build leaves out the copies onnxruntime brings (24 MB nobody asks for; `vite.config.js`). `onnxruntime-web` stays at the exact version `@imgly/background-removal` asks for.

They ran on GitHub Pages at `skalpel.sanakan.pl` and `uskalpel.sanakan.pl` before; those names lead to the site by two redirect rules in Cloudflare (Rules → Redirect Rules, a single redirect each: hostname `skalpel.sanakan.pl`, dynamic target `concat("https://sanakan.pl/skalpel", http.request.uri.path)`, 301, query string kept; the same for `uskalpel`), with their DNS records proxied. The server never sees those names.

## Running locally

The whole site, without the wiki, runs locally with made-up data, to look at and test (Git Bash or any shell with PHP 8.1 or newer):

```bash
tools/preview.sh              # http://127.0.0.1:8765/, or tools/preview.sh 8080
tools/preview-stop.sh         # stops it; with --clean also removes its data
tools/preview.sh --reset      # the made-up data from scratch
```

Direct event and skin previews, no login needed: `http://127.0.0.1:8765/?event=<key>` sets the simulated date (`safeguard-date`) to the next day of that event before the site scripts run, a day without other events where one exists. Keys: `xmas`, `newyear`, `easter`, `aprilfools`, `birthday`, `halloween`, `friday13`, `sakura`, `perseids`, `fireflies` (the keys of `SAFEGUARD_SEASONAL` in `inc/auth/finds.php`, so a new event works here at once); `?event=none` goes back to today. The date stays in the host's browser storage, and different hosts (`127.0.0.1`, `localhost`) keep their own, so two events can stay open at once. `?skin=<key>` previews any skin of `inc/skin-catalog.php` (`teto`, `miku`, `echidna`, `marisa`, `fauna`, `padoru`, `reisen`, `peko`, `ayame`, `albedo`, `tomie`, `lain`, `cibo`, `killy`, `march7`, `shogun`, `suisei`, `hoshino`, `firefly`, `yoimiya`) for that page visit, without saving an account preference; both combine, e.g. `?event=fireflies&skin=yoimiya`.

It runs `php -S` with `tools/preview/router.php`, which does what nginx does on the server (`inc/` and the dot files kept out, the gallery's links of the accounts' folders, the short links of the commands, the security headers of `server/nginx/`, the croppers' own), and a made-up bot API next to it on the following port (`tools/preview/bot-api.php`: the roles, the commands, `api/health`). `tools/preview/cron.php` runs the site's own `inc/check-bot.php` every minute, so the status keeps its history and uploaded pictures are changed to WebP. The data lives in `.preview/data` (with the logs in `.preview/`, out of git), filled the first time by `tools/preview/seed.php`: 24 hours of checks with an outage, 120 days of availability with a planned break, the versions, a week of changes in the commands, the other sites, a notice saying the data is made up, an access request and a few pictures in the gallery (`i/Podgląd`). `/__login` (where every login of the site goes in the preview, never to Discord) logs in as one of the accounts of `tools/preview/data.php`: dev with the panel and the whole gallery, admin, moderator, user, and a guest without a role. Its settings are `tools/preview/config.php` instead of `inc/config.php`, so it refuses to start while there is one. `npm run dev` of a cropper (apps/) takes the site from it.

## Tests

The logic that can be tested without a browser or the network has a small, dependency-free suite; no composer, so it runs on the server's PHP too:

```bash
php tests/lint.php   # php -l over every PHP file
php tests/run.php    # the cases, no network
php tests/http.php   # HTTP smoke test of the pages, no network
node --test apps/*/test/*.test.mjs   # the croppers' code that runs without a page
```

Every `tests/test_*.php` registers cases with `test('name', function () { ... })` and asserts with `assertSame()`, `assertTrue()`, `assertContains()`, `assertThrows()` (see `tests/bootstrap.php`). The bootstrap points `SITE_DATA_DIR` at a temporary folder before the code is loaded, so a test never touches `inc/data`; `tests/run.php` clears it between two cases. To cover a pure function, add a `tests/test_*.php` (the suite picks it up by name); to change the data folder of a real install, set `SITE_DATA_DIR` in `inc/config.php`. The session tests start a real session in the CLI; the GD and ZIP tests run only when `gd` and `zip` are loaded, and in CI (where `CI` is set) a missing one fails them instead of leaving them out.

The network is faked through `httpRaw()` (inc/auth.php): with the `SANAKAN_HTTP` callable set, it is called instead of `file_get_contents`, so a test can script Discord, the bot API and Cloudflare. `tests/http.php` starts the real site with `php -S` and `tests/smoke-router.php`, which points the bot API at `tests/bot-stub.php` on a second server (so the single-threaded site server never asks itself) and `SITE_DATA_DIR` at a temporary folder; it then asks every page for its status and that its body has no PHP error. `BOT_API_BASE` in `inc/config.php` points the bot API elsewhere (a test bot), the live address is the default.

Covered: the text helpers and Polish plurals, the safe paths, the file names, the media sniffing and metadata stripping (JPEG/PNG/WebP/AVIF), the byte ranges, the access lists and roles, the session, the logged-in account and the test rights, the Discord login and the bot API through the fake network, the bot state (commands, days, incidents, API, dependencies, heartbeat, addresses, versions), the changelog parser, the Markdown renderer and the @nick avatars, the command and log parsers, the availability analysis and the nginx log reading, the trash, its budget and the limits of a restore, the cleanup and the log of operations, the shared links, the background conversion queue, the ZIP walk and a real ZIP by the visitor's rights, the limits of pictures by their headers, the search, the storage of `inc/data` (whole writes, broken files, several processes at once with a reader), how the code is split (`tests/test_modules.php`: every function in one place, the modules only defining things, a whole document written over only where that is meant), the headers of the thumbnails and the pages through the HTTP smoke test, and the croppers' blob: addresses, decoded pictures and frames through `node --test`.

Not unit-tested: the DNS reverse lookup of the automatic blocking (`autoBlockTrustedHost()`), the external tool conversions (`cwebp`, `ffmpeg`) beyond the GD path, and the croppers' gestures beyond their JavaScript unit tests. `tests/browser.mjs` runs the site in Chromium with disposable PHP data, including the home page and skin regressions in `tests/home-browser.mjs` and `tests/skins-browser.mjs`, and seasonal date boundaries, catches, retries and unlocks in `tests/seasonal-browser.mjs`, (`BROWSER_ONLY=seasonal,theme node tests/browser.mjs` runs only the named parts, of `storage`, `core`, `home`, `skins`, `seasonal`, `custom`, `picker` and `theme`, while working on them; the whole suite before a commit), and nginx itself (the headers on the server are checked after a deploy).

GitHub Actions runs the lint, the suite and the HTTP smoke test on PHP 8.5, the server's, and on 8.1, the oldest the code keeps working on (a deprecation notice of PHP fails the lint, the suite and the smoke test, so a newer PHP's are seen before the server shows them), and `node --check` on the scripts and the croppers' tests with Node.js 22, which also builds Skalpelator and USkalpelator and checks the build matches the one committed (`.github/workflows/ci.yml`). `tests/`, `.github/`, `tools/` and `apps/` are `export-ignore`, so `deploy.sh` never sends them to the server.
