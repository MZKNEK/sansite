# Repository layout

What each file and folder holds, what stays out of git and how a backup of the data goes back. The other documents are listed in the [README](../README.md).

| Path | Contents |
|---|---|
| `index.html`, `404.html` | Home page and the 404 page |
| `401.html`, `403.html`, `500.html` | The other error pages: a login needed (the admin panel, a moderator or debug command on `/cmd/`, and the gallery's ZIP of a folder, without one, with a login that comes back to the same address), an address refused (by nginx, or the gallery's ZIP of a folder the account may not see), and a failure of the server (nginx's, PHP-FPM down or too slow, or a PHP page's own, an uncaught exception or a fatal error, for which `installDataErrorHandler()` in `inc/storage.php` sends it to a browser and JSON to a script; with `display_errors` on, PHP's own message of a fatal error stays), which asks PHP for nothing |
| `sw.js`, `offline.html` | The service worker and the page it shows without a network; its list of files carries their `?v=`, so a change to the page installs it anew |
| `palette.php` | The commands and versions for the search of every page (`js/palette.js`) |
| `megastructure.php`, `inc/megastructure.php` | The hidden way to the Net Terminal Gene, the hardest easter egg (see [safeguard.md](safeguard.md)): what the 404 page, the motto, the console and the terminal ask, answered from `SAFEGUARD_SECRET` |
| `og.php`, `inc/og.php` | Link preview pictures (`og:image`) of the pages, drawn with GD: the home page the logo with the bot's live Discord status dot (kept a minute); the commands their number and modules, their change history the latest changes with the new text of what changed, new commands of the last 30 days always among them (10 minutes); the version history the current version, how many there were and the last ones as commits on a branch, one version its number, how many changes it brought and the first of them, or without any its place on that branch (10 minutes); the panel a radar with the bot in its centre and the Sanakan sites as blips in the colours of their last check (5 minutes); the gallery, the API, the privacy notice and the profile (an identity card of the Safeguard, everything on it unknown) a drawing without any data (a day); Skalpelator and USkalpelator as their old fixed pictures had them, drawn live: the title in its purple glow, the example picture each app opens with (`i/ss/` of the gallery, Sanakan's own picture without it) with the crop on it, an arrow and the card it makes, put together as the app puts it from the mirrored pictures of the bot's cards (`inc/pw.php`; USkalpelator's with the top layer, so the hair goes over the frame), and the page without them before cron has those pictures (6 hours). `state/og.php` draws the status one (availability, outages, version, and Shinden, Alter and the bot API as dots) with the same code |
| `img/` | The site's own pictures, moved out of the root (nginx answers their old root addresses with a 301 to `img/`, `server/nginx/sanakan.conf`, as the preview's router does): |
| `img/sanakan-og.png` | The home page's picture without the status dot, sent when GD cannot draw |
| `img/wiki-og.png` | The wiki's link preview picture, a fixed file (a fan of Pocket Waifu cards), set by `server/wiki/nginx-og.conf` |
| `img/logo.webp` | The home page's logo, also the one in the link preview pictures and the example picture of the croppers' previews without `i/ss/` |
| `skins/` | The logos the skins of the home page wear (teto.webp, miku.webp, echidna.webp, marisa.webp, fauna.webp, padoru.webp, reisen.webp, peko.webp, ayame.webp, albedo.webp, tomie.webp, lain.webp, cibo.webp, killy.webp, march7.webp, shogun.webp, suisei.webp, hoshino.webp), referenced by `inc/skin-catalog.php`, its generated `js/skin-catalog.js` and `css/skins.css` |
| `favicon.ico`, `img/favicon.svg`, `apple-touch-icon.png`, `img/favicon-*.png`, `site.webmanifest` | The site's icons; the PNGs of 192, 256 and 512 pixels are listed in the manifest for Android, with `favicon-maskable-512x512.png` (the icon at 60 % on a full square, inside the safe zone) for the launchers that cut it to a circle or squircle; the manifest's `display: standalone` lets the site be installed as an app; `favicon.ico` and `apple-touch-icon.png` stay in the root, where browsers ask for them without a link |
| `cmd/`, `api/`, `state/`, `i/`, `admin/`, `account/`, `hunters/` | Subpages |
| `profilator/` | Profilator: `index.php`, `profile.js` (the bot's profile drawn as the bot draws it, and its profile code), `profilator.js` (the page) and `profilator.css` |
| `apps/skalpel/`, `apps/uskalpel/`, `apps/shared/` | The sources of Skalpelator and USkalpelator (Svelte and Vite) and the code they share (the crop, its worker, the fields of their panels, their Vite configuration, vite.mjs), sent on the server never |
| `skalpel/`, `uskalpel/` | Their build, written by `tools/build-apps.sh` and committed, so the server serves plain files and needs no Node.js for them |
| `status.php` | Bot status for the home page |
| `alive/` | The bot's report sent by the bot itself, kept for `inc/bot.php` |
| `inc/bot.php` | Bot API access: the bot's `api/health` (Discord connection and ping, database, Shinden, commands; the command list where a bot has no `api/health` yet), one-minute cache, 24 h check history with the ping, per day counts, outages, notice and maintenance breaks, last known command list and its changes, the versions it reported and when they changed, the moderator and debug commands fetched with the site's key |
| `inc/check-bot.php` | One bot check, run by cron every minute; every 5 minutes also the other sites, once a day it removes the thumbnails nobody looked at for 30 days, and it changes the pictures and films uploaded since the last run to WebP or WebM in the background |
| `inc/maintenance.php`, `inc/run-maintenance.php` | The cleanup of the gallery's data, run by its own cron job every 10 minutes: operations on the trash cut short are finished or undone from their notes in `inc/data/operations/`, and the trash past its days is deleted within a time budget (`--dry-run` by hand) |
| `inc/media-worker.php` | Changes the pictures and films waiting as WebP or WebM; an upload starts it at once in the background, `inc/check-bot.php` does the same from cron, and it can be run by hand, e.g. after cron was off |
| `inc/system.php` | The server's resources for the panel, read from Linux's `/proc` when the panel opens (the processor use comes from the background check, `inc/diag.php`, so opening the panel does not wait) |
| `inc/diag.php`, `inc/check-site.php` | Availability of the site, checked by cron every 10 seconds through Cloudflare and straight on the server, with the kernel's TCP counters, the state of nginx and PHP-FPM, the use of the processor and memory and the requests from the site's nginx log; the scanners and the PHP time per page from the same log; kept 3 days in `inc/data/diag/` (left out of the backup) |
| `inc/cloudflare.php` | Blocking addresses in Cloudflare from the panel, through an IP list of the account |
| `inc/autoblock.php` | Blocking scanners in Cloudflare automatically, run by `inc/check-site.php` once the panel turned it on |
| `inc/panel-account.php`, `inc/panel-search.php` | The profile of an account and the search of the panel |
| `inc/services.php` | The Sanakan sites, this one included: whether they answer, since when, per day counts |
| `inc/storage.php` | The JSON files of `inc/data`: a change locks the file's own lock file (`inc/data/locks/`), reads it fresh from the disk, makes the change and writes it whole or not at all (a new file, flushed to the disk and renamed over the old one), so requests and cron at once lose nothing and readers never see half a file; data that cannot be JSON, such as text that is not UTF-8, is refused and the old file stays; a broken file is read as empty but never written over by a change (`readData()`, `updateData()`, `writeData()`, `replaceFile()`). The bot's state files and the summaries of diag go the same way |
| `inc/auth.php`, `inc/auth/` | Discord login (OAuth2), a session of a week kept in `inc/data/sessions/` (one without an account or a shared folder goes after an hour unused; a cookie naming no stored session starts none), access lists, the account's roles on the bot's server (asked with the site's key, kept 10 minutes), change history. `inc/auth.php` loads its parts from `inc/auth/` (`config`, `history`, `permissions`, `roles`, `preferences`, `finds`, `menu`, `requests`, `session`, `addresses`, `oauth`) |
| `inc/gallery.php`, `inc/gallery/` | Gallery: thumbnails (also of videos), uploads without metadata, pictures changed to WebP and films to WebM in the background, the manual change to WebP with a quality and a preview, search, trash, renaming, rotating, ZIP downloads. `inc/gallery.php` loads its parts from `inc/gallery/`, a file for each (`paths`, `access`, `accounts`, `media`, `limits`, `metadata`, `thumbnails`, `listing`, `shares`, `export`, `moved`, `previews`, `jobs`, `trash`, `uploads`, `operations`…) |
| `inc/admin/` | The admin panel's parts, loaded by `admin/index.php`, which keeps the login, the rights and the CSRF check: `format.php` and `charts.php` (what its pages write), `actions.php` (every change, `panelAction()`), `view-data.php` (what the main page shows, `panelOverviewData()`) and `views/` (the cards of each part of the page) |
| How the parts are split | The files in `inc/auth/`, `inc/gallery/` and `inc/admin/` only define functions and constants: loading one sends, reads and runs nothing, and every function has one place (checked by `tests/test_modules.php`) |
| `inc/pw.php` | The pictures of the bot's cards for Skalpelator and USkalpelator (the frames, the deres, the stars, the layers of the ultimate cards), mirrored by cron from the bot's repository (`src/Pictures/PW` of `MZKNEK/sanakan`) into `inc/data/pw/` and served at `/pw/`: every 6 hours GitHub's list of the folder's files, then only the files whose content changed, each checked against its git hash, at most 40 seconds a run; a file gone from the repository or changed on the disk is put right too. `variants.json` with them says how many styles each ultimate frame has, read from the bot's `GetCardVariantsCount()`. The panel's server card shows its state; the backup leaves it out, as cron makes it again. `inc/pw-sync.php` (as `www-data`, with `--force` to ask GitHub before the 6 hours) syncs it whole at once, e.g. right after the first deploy, as does the button "Pobierz teraz" of the panel's server card. The pictures of the profile come the same way into `np/` for Profilator: the bot's `src/Pictures/np` and its two panels of list statistics, `statsAnime.png` and `statsManga.png` (`pwSourcePath()` finds each in the repository again) |
| `inc/text.php` | Escaping, lower case, Polish plurals, byte sizes and thousands, what changed between two texts, and text from outside with what is not UTF-8 replaced, shared by every page (`e()`, `plural()`, `formatSize()`, `textDiff()`, `validText()`) |
| `inc/panel-stats.php` | The gallery's numbers and the room `inc/data` takes, counted by `inc/check-bot.php` in the background and only read by the panel |
| `inc/status-card.php`, `inc/meta.php` | Bot status card and link preview tags (Open Graph) |
| `inc/verdiff.php`, `inc/verdiff-builtin.md`, `inc/markdown.php` | The bot's changelog (`verdiff.md` in its repository, read over HTTP and cached; the versions from 1.0.0.0-alpha to 1.4.10.13, which the file never described, written in `inc/verdiff-builtin.md` from the bot's commits and listed on the page even when the bot never reported them), the @nick of a known account as its avatar, and the small dependency-free Markdown renderer the version history `state/versions/` uses |
| `fonts/`, `css/fonts.css` | The site's fonts (Lato, Sanakan Mono, JetBrains Mono, SIL Open Font License; Sanakan Mono is Share Tech Mono with the Polish letters it lacks added), served from the site instead of Google Fonts, so no visitor's address goes to Google |
| `inc/fonts/` | Lato and Sanakan Mono (SIL Open Font License) for the preview picture of `/state/` |
| `privacy/` | Privacy notice for the site, bot and API, with controls for saving discoveries, linked from every footer |
| `terms/` | Terms of use, linked next to the privacy notice in every footer |
| `inc/config.example.php` | Configuration template |
| `css/`, `js/` | Styles and scripts; the account menu's styles in `css/account.css` and the search's in `css/palette.css`, which every page links after `css/style.css` (the croppers without it) |
| `robots.txt` | Keeps search engines out of the gallery, the panel, the profile, `inc/`, the API documentation and the ranking of the hunters |
| `server/nginx/` | nginx: the site's server block (https from Cloudflare with its Origin Certificate), blocked `inc/`, the 404, 403 and 500 pages, short links to commands, security headers (Skalpelator's and USkalpelator's of their own), browser cache, visitors' addresses behind Cloudflare, the site's log and the state of nginx and PHP-FPM for the server itself |
| `server/ufw-cloudflare.sh` | The server's firewall: SSH for everyone, port 443 only for Cloudflare (see Firewall in `docs/server.md`) |
| `server/wiki/` | The site's look for the wiki (Wiki.js 2, dark mode): `theme.css` and `head.html` pasted by hand into its Administration → Theme → Code Injection (CSS Override, Head HTML), `nginx-site.conf`, its nginx server block, with `nginx-og.conf` (its link preview picture and purple), and in `assets/` the site's icon in the sizes Wiki.js uses, with its manifest, copied over the wiki's own `assets/` (see Wiki in `docs/server.md`) |
| `tools/` | Development helpers, sent on the server never: `asset-versions.php` rewrites the `?v=` of every CSS and JS in the pages (and of the offline page's files in `sw.js`) to the first ten characters of the file's hash, and `install-hooks.sh` makes git run it before every commit, so the version follows the content without anyone raising a number by hand; `build-apps.sh` builds Skalpelator and USkalpelator; `preview.sh` and `preview-stop.sh` run and stop the local preview with made-up data (`preview/`, see [development.md](development.md)); `gallery-upload.sh` sends a folder of the local `i/` to the same path in the server's gallery (see Adding a folder to the gallery in `docs/server.md`) |
| `tests/`, `.github/` | The dependency-free test suite (`php tests/run.php`, `php tests/lint.php`) and the CI that runs it, also sent on the server never (see [development.md](development.md)) |
| `deploy.sh` | Deployment to the server over SSH |
| `migrate.sh` | Moving the site and the wiki to a new server (see Moving to a new server in `docs/server.md`) |

Kept out of git:
- `inc/config.php`, which holds the Discord application secret,
- `inc/data/`, the data the site writes: access lists and requests, the roles the bot reported, status history and outages, change history, version changes and the changelog read from the bot's repository, trash, the old links of pictures changed to WebP and of films changed to WebM, the pictures and films waiting as WebP or WebM (`media-jobs.json`), the WebP results of a manual change waiting to be accepted (`webp-previews.json`, their files in `webp-preview/`), the WebP conversion qualities and the automatic scanner blocking (`settings.json`), the time sessions are valid from, the thumbnail cache (`thumbs/`, left out of the backup), the empty lock files of the data (`locks/`, also left out; never to be removed while the site runs), the notes of operations on the trash in progress (`operations/`) and how the last cleanup went (`maintenance.json`), and the gallery and `inc/data` numbers the panel shows (`panel-stats.json`, counted by cron),
- the pictures in `i/` (only `i/index.php` is tracked).

The panel downloads `inc/data/`, optionally with the pictures, as one ZIP (server card, "Kopia danych"). To restore it, unpack `data/` into `inc/data/` and `i/` into `i/`, then give them back to the web server: `chown -R www-data:www-data inc/data i`.
